# Release 実機テスト手順書

基準日: 2026年7月14日  
対象アプリ: あしたもつもの  
Application ID: `com.ashita_motsumono`

本書は、Google Play内部テストおよびiOS/TestFlight相当の正式候補ビルドについて、端末依存機能、外部サービス、データ保護、復旧性を人間が実機で確認するための手順です。

## 1. 目的

次を、CIやWidgetテストではなく正式候補ビルドをインストールした実機で検証します。

- 初回起動、アップグレード、再起動後の安定性
- 人物、Todo、チェックリスト、読み取り文書の基本操作
- 端末内SQLite/SharedPreferences/画像保存の永続性
- カメラ、画像選択、日本語OCR
- 任意AI画像解析の説明・同意・通信・結果
- ローカル通知、端末再起動後、アプリ更新後の再予約
- AdMob本番広告、広告失敗時のフォールバック、広告除去
- Google Play Billing / Apple IAPの購入、取消、復元
- データ削除、JSONエクスポート、DB障害時の復旧UI
- オフライン、タイムゾーン、バックグラウンド、権限拒否
- プライバシー・ストア開示との一致

## 2. 非目的

- CI成功を実機テスト成功とみなさない
- テスト用署名・サイドロードだけでPlay/App Store配布を合格としない
- ストア審査通過を機能品質の代替にしない
- AI解析結果の完全な正確性を保証しない
- OSや端末メーカーのすべての組合せを網羅しない

## 3. 開始条件

- [ ] 対象commitが`origin/master`上の承認済みcommitである
- [ ] 作業ツリーがcleanである
- [ ] CIのAnalyze/Test/契約テストが成功している
- [ ] 正式署名済みAndroid AAB/APKまたはTestFlight buildがある
- [ ] `release-manifest.json`、成果物ハッシュ、証明書照合がある
- [ ] Play App Signing/Apple署名設定が完了している
- [ ] 内部テスト/内部配布のテスターとして対象アカウントが登録済み
- [ ] AdMob本番App ID/広告ユニットが設定済み
- [ ] `GEMINI_PROXY_URL`がHTTPS本番URLである
- [ ] 課金商品が対象トラックで利用可能
- [ ] 商品IDがビルド設定と一致する
- [ ] プライバシーポリシー、サポートページが公開済み
- [ ] [ストア開示整合性チェックリスト](../store/store-disclosure-consistency-checklist.md)の対象・公開前ゲートを確認済み
- [ ] テスト用の学校・園のお知らせ画像を用意し、実在人物・学校の情報を含めない

開始条件を満たさない場合は、結果を`BLOCKED`として不足条件を記録します。

## 4. テスト対象の固定

[release-test-results-template.md](./release-test-results-template.md)へ次を記録します。

- commit SHA
- ブランチ/タグ
- versionName/versionCodeまたはiOS version/build
- 配布トラックとストアURL/Build番号
- APK/AAB/IPAまたはmanifestのSHA-256
- Application ID / Bundle ID
- AdMob設定識別子（秘密値そのものは記録しない）
- 課金商品ID
- Gemini Proxyのホスト名（クエリ/秘密値は記録しない）
- テスト開始・終了日時、タイムゾーン

## 5. 最小端末マトリクス

### Android必須

| 区分 | 条件 | 目的 |
|---|---|---|
| A1 | Android 13以上、Pixel系または標準Android、内部テスト版 | POST_NOTIFICATIONS、Photo Picker、標準動作 |
| A2 | Android 14/15/16相当、別メーカー実機 | バッテリー制限、再起動、通知差異 |
| A3 | サポート下限に近いAndroid、実機または高忠実度端末 | 互換性、権限・画像選択差異 |

少なくとも1台は、Play Storeの内部テストリンクからインストールします。通知のnormal/reboot/install-r検証に既存の`emulator-5554`証跡を利用する場合でも、最終リリース判定には実機での主要通知確認を追加します。

### iOS必須

| 区分 | 条件 | 目的 |
|---|---|---|
| I1 | 現行iOS、iPhone実機、TestFlight版 | カメラ、写真、通知、IAP、AdMob、ATT |
| I2 | サポート下限に近いiOS、可能なら別画面サイズ | 互換性、権限、レイアウト |

iOS正式成果物がない場合、iOS全項目を`BLOCKED`としてAndroid合格と分離します。

## 6. テストアカウントとデータ

- 広告除去を未購入のストアテストアカウント
- 広告除去を購入済みまたは復元可能なアカウント
- AI分析を未購入のアカウント
- AI分析を購入済みまたは復元可能なアカウント
- 購入保留/取消を再現できるテスト環境
- 活字の日本語お知らせ画像
- 手書きを含む画像
- 文字なし画像
- 暗い/傾いた/大容量の画像
- 複数Todo、期限、金額、持ち物を含む画像
- 個人情報を含まない合成データ

## 7. 判定基準

- **PASS**: 期待結果を満たし、必要証跡がある
- **FAIL**: 期待結果と異なる
- **BLOCKED**: 環境、設定、権限、商品、管理画面等の不足で実行不能
- **INCONCLUSIVE**: 実行したが、証跡不足または外部要因により成否を確定できない
- **N/A**: 対象外。理由が必要

証跡のない口頭確認はPASSにしません。

## 8. 共通証跡

各ケースで必要に応じて次を保存します。

- 操作前後のスクリーンショット/画面録画
- OS権限画面
- アプリバージョン画面
- Play/TestFlight配布画面
- 通知領域/ロック画面
- Android: `adb shell dumpsys package`、`dumpsys alarm`、`dumpsys notification`、対象を絞ったlogcat
- iOS: Xcode device logs、Consoleログ、TestFlight build情報
- ストア購入ダイアログと復元後画面（注文番号・アカウント情報はマスク）
- ネットワーク失敗時のアプリ画面
- 欠陥ID

秘密値、購入トークン、APIキー、児童氏名、学校名、実画像原本をリポジトリへ保存しません。

## 9. テストケース

## 9.1 インストール・起動・アップグレード

### DEV-001 新規インストール

1. 対象アプリを未インストールの端末を用意します。
2. Google Play内部テストまたはTestFlightからインストールします。
3. 初回起動します。
4. ホーム画面まで到達し、致命的エラーがないことを確認します。

期待結果:

- 公開名称が「あしたもつもの」
- デバッグバナー、テスト用URL、localhost表示がない
- 空状態が理解可能
- 不要な権限を起動直後に一括要求しない
- 主要操作が可能

### DEV-002 既存版からの更新

1. 旧リリース版で人物、Todo、画像付き文書、通知を登録します。
2. アプリを終了します。
3. ストア経由で候補版へ更新します。
4. 起動して登録内容を確認します。

期待結果:

- 人物、Todo、チェックリスト、画像、OCRテキスト、通知設定、購入済み状態が維持される
- DB migration後に孤立参照やクラッシュがない
- 更新後に通知が再予約される
- 既存データを空スナップショットで上書きしない

### DEV-003 強制終了・再起動

編集中、保存後、OCR後、購入処理前後でアプリを終了・再起動します。

期待結果:

- 保存完了前の不完全データが公開されない
- 保存済みデータが復元される
- 起動不能時は復旧UIが表示され、データを上書きしない

## 9.3 カメラ・画像選択・通常OCR

### DEV-020 カメラ許可

1. カメラ機能を選択します。
2. 初回権限を許可します。
3. 活字の日本語画像を撮影します。

期待結果:

- 認識結果を修正可能
- 文書・画像が再起動後も参照可能
- 通常OCRでAI同意画面が出ず、Workers/Geminiへ送信しない

### DEV-021 カメラ拒否

初回拒否、再要求、恒久拒否相当を確認します。

期待結果:

- クラッシュしない
- 適切な案内がある
- 手入力/画像選択等の代替手段が使える
- Todo作成自体を妨げない

### DEV-022 画像選択

OSのPhoto Picker/画像選択から1枚を選びます。キャンセルも確認します。

期待結果:

- 選択した画像だけを処理
- キャンセルで文書/画像ゴミを残さない
- 不要な広範囲ストレージ権限を要求しない

### DEV-023 OCR失敗・空画像

文字なし、暗い、傾いた、大容量、破損画像を試します。

期待結果:

- 理解可能なエラーまたは空結果案内
- 手入力へのフォールバック
- 失敗時の作業画像を削除

## 9.4 AI画像解析

### DEV-030 未購入状態

期待結果:

- AI利用権がない場合、購入導線または利用不可状態が正しい
- 通常OCRは利用可能

### DEV-031 同意キャンセル

1. AI解析を選択します。
2. 外部送信説明を確認します。
3. キャンセルします。

期待結果:

- 画像、画像形式、基準日、タイムゾーンを送信する説明がある
- Cloudflare Workers経由でGoogle Gemini APIへ送信する説明がある
- 通常OCRは外部送信しない説明がある
- キャンセル時に画像選択を開始しない
- HTTP通信を開始しない

### DEV-032 同意して成功

1. 同意後に個人情報を含まないテスト画像を撮影します。
2. 解析を実行します。
3. Todo候補を確認・修正して保存します。

期待結果:

- HTTPS本番Proxyへ送信
- 60秒以内または設計済みタイムアウトで応答
- タイトル、カテゴリ、期限、金額、持ち物、メモの候補を表示
- 誤認識を修正可能
- 保存後に文書/画像が端末内で参照可能
- APIキーが端末ログ/リクエスト本文に含まれない

### DEV-033 AI通信失敗

オフライン、DNS失敗、タイムアウト、5xxを確認します。

期待結果:

- ネットワーク/サーバー/タイムアウトに応じたエラー
- クラッシュしない
- 失敗した作業画像を削除
- 既存データを変更しない
- 通常OCR/手入力へ戻れる

### DEV-034 AI解析内容の安全確認

- 氏名、顔、学校名、住所等を含む実データを使わない
- 合成画像で、送信前説明とプライバシーポリシーが一致することだけを確認
- Todo候補を自動確定しない

## 9.5 通知

### DEV-040 通知権限許可/拒否

期待結果:

- Android 13+またはiOSで適切なタイミングに許可を求める
- 拒否時もTodoを保存できる
- 設定画面への案内がある

### DEV-041 通常通知

1. 現在時刻から十分な余裕を持つ通知Todoを作成します。
2. アプリをバックグラウンドへ移します。
3. 端末をスリープ状態にします。
4. 予定時刻に通知を確認します。

期待結果:

- 予定したTodoの通知が1回届く
- タイトル/本文が対象Todoと一致
- タップで適切な画面へ遷移、または安全にアプリが開く
- 通知ID衝突による上書きがない

### DEV-042 端末再起動後

1. 通知を未来に設定します。
2. 端末を通常再起動します。
3. 起動完了後、アプリを不要に開かず予定時刻まで待ちます。

期待結果:

- AndroidではBoot Receiver経由で通知が再予約される
- 通知が予定時刻に届く
- Source SHA、boot ID、Alarm証跡を保存

### DEV-043 アプリ更新後

1. 旧版で通知を予約します。
2. ストア更新またはAndroidの安全な`install -r`相当で更新します。
3. 予定時刻まで待ちます。

期待結果:

- MY_PACKAGE_REPLACED/更新後の再予約が機能
- 既存通知が重複しない
- Todoデータが維持される

### DEV-044 通知編集・削除

通知日時変更、通知OFF、Todo削除を行います。

期待結果:

- 古い通知を取消
- 新しい通知だけが届く
- 削除済みTodoの通知が届かない
- 取消失敗時は再試行キューへ残り、後で解消する

### DEV-045 タイムゾーン/壁時計

端末のタイムゾーンをテスト可能な範囲で変更し、通知予定表示と実通知を確認します。

期待結果:

- Todoの通知計画が端末の壁時計時刻として扱われる
- 再予約後に新しいタイムゾーンと一致
- AI解析は現実装で`Asia/Tokyo`固定である点を別途記録

- AdMob、2商品、削除、エクスポート、端末内ログの説明が一致
- 実際にないログイン/同期/クラウド保存を記載しない

## 10. 欠陥の重大度

| Severity | 定義 | 例 |
|---|---|---|
| S0 Critical | データ漏えい、課金不正、広範囲データ消失、公開停止が必要 | 同意なし画像送信、購入失敗で権利付与、全Todo消失 |
| S1 High | 主要機能不能、再現性の高いクラッシュ、通知/購入/削除の重大不整合 | 正式版が起動しない、削除済み通知が届く、復元不能 |
| S2 Medium | 回避策がある機能不良、限定環境の不整合 | 特定端末だけOCR失敗、レイアウト崩れ |
| S3 Low | 表示、文言、軽微なUX | 誤字、余白、非主要画面の軽微な崩れ |

S0/S1はリリースブロッカーです。プライバシー・ストア開示の誤りは、影響に応じてS0またはS1とします。

## 12. 総合判定

- **PASS / READY_FOR_SUBMISSION**: すべての終了条件を満たす
- **CONDITIONAL_PASS**: S2以下のみ。影響・回避策・承認者を記録

# OCR品質ベンチマーク

基準日：2026-08-05  
対象：`kaenozu/ashita-motsumono`  
目的：OCR・候補抽出の品質を、匿名化済み実データ30件以上で再現可能に評価する。

## 現在の判定

`BLOCKED_REAL_DATA_NOT_COLLECTED`

評価基盤と集計ツールは用意されていますが、実プリント・PDF・スクリーンショット30件以上の結果はまだ入力されていません。人工fixture、Widget test、CI成功を実データ品質の代替にしません。

## データ取扱い

実プリントはリポジトリ外のローカル領域だけで扱います。

GitHubへ保存しないもの：

- 原本画像・PDF
- OCR全文・元文
- 児童名、学校名、教員名
- 住所、電話番号、メールアドレス
- QRコード
- ローカルファイルパス
- 個人を再識別できるスクリーンショットやログ

通常OCRと、外部サービスを使用するAI画像解析は別のデータセット・判定として記録します。

## 推奨データ構成

30件以上を最低条件とし、偏りを避けます。

- 通常の印刷お便り
- 表形式
- 複数ページPDF
- スクリーンショット
- カメラ撮影
- 斜め、影、低コントラスト
- 小さい文字
- 手書き混在

印刷文書が0件の場合、30件以上でも集計結果は`BLOCKED`です。

## 文書ごとの記録

`tool/ocr_benchmark/benchmark_template.json`をリポジトリ外へコピーし、次を記録します。

| 分類 | 主な項目 |
|---|---|
| 入力 | `input_type`, `page_count`, `ingest_success` |
| OCR | `ocr_success`, `ocr_empty`, `processing_time_seconds` |
| 日付 | 正解候補、誤候補、期待件数 |
| 持ち物等 | 正解候補、誤候補、期待件数 |
| 修正負担 | 不要候補、抽出漏れ、修正回数、修正なし登録 |
| 回復性 | 手動修正後登録、手入力フォールバック |
| 安全性 | クラッシュ、データ破損、誤期限の無確認登録 |

原文やOCR全文は記録しません。

## 自動集計

```bash
python3 tool/ocr_benchmark/summarize.py benchmark.json --output summary.json
```

入力検証では、個人情報・原文を示すキー、重複ID、不正型、件数不一致、矛盾した成否を拒否します。

集計指標：

- 取り込み成功率
- OCR空結果率
- 日付precision / recall
- 持ち物等precision / recall
- 修正なし登録率
- 手動修正後登録率
- 平均修正回数
- p95処理時間
- クラッシュ率
- データ破損件数
- OCR失敗時の手入力移行率
- 誤った期限の無確認登録件数

## 自動判定基準

| 指標 | 基準 |
|---|---:|
| 文書数 | 30件以上 |
| 取り込み成功率 | 95%以上 |
| クラッシュ／データ破損 | 0件 |
| 印刷文書の修正なし登録率 | 70%以上 |
| 手動修正後に登録可能 | 95%以上 |
| OCR失敗時の手入力移行 | 100% |
| 誤った期限の無確認登録 | 0件 |

p95処理時間には端末性能と文書条件が影響するため、ツールは値を報告するだけで自動閾値を設定しません。端末、Androidバージョン、入力形式、目視した操作性と合わせて判定します。

## 判定語

- `BLOCKED`: 30件未満、印刷文書なし、または必要証跡が不足
- `FAIL`: 十分な件数があり、基準違反を検出
- `PASS`: 30件以上で自動基準を満たす

`PASS`であっても、実機での全入力経路、通知、購入復元、アップグレード、Play配布の受入を代替しません。

- 実機またはエミュレータでOCR導線を実行可能
